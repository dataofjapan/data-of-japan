# データソース

「参議院選挙で、誰が立候補し、誰が当選したか」のデータソース調査と、データ層の設計方針。
調査日: 2026-09-26。URL と表の中身は取得して確認済み。

## 1. 結論

一次情報源は総務省「参議院議員通常選挙結果調」（兄弟サイト election-sangiin-timeseries と同じ）。
各回の結果ページにある、候補者数と当選人数の次の4表を使う。

| id | 表 | 次元 |
| --- | --- | --- |
| `candParty` | 党派別男女別新現元別候補者数（選挙区、比例代表） | 党 × 制度 × 新現元 × 男女 |
| `candPref` | 都道府県別党派別新現元別候補者数（選挙区） | 選挙区 × 党 × 新現元。定数の列 |
| `winParty` | 党派別男女別新現元別当選人数（選挙区、比例代表） | 党 × 制度 × 新現元 × 男女 |
| `winPref` | 都道府県別党派別新現元別当選人数（選挙区） | 選挙区 × 党 × 新現元。定数の列 |

範囲は兄弟サイトと同じ第19〜27回（2001–2025）。形式は第19回が HTML、第20回が PDF、第21回以降が Excel。

- 衆議院の兄弟サイト（shugiin-candidates）にある年齢段階別の表は、参議院の結果ページにはない（公示前の速報資料にだけある）。年齢のビューは作らない。
- 都道府県別の表は選挙区だけで、男女別の内訳はない。

出典表記: 総務省「参議院議員通常選挙結果調」。

## 2. 回ごとの目録

正本は [`src/lib/data/elections.ts`](../src/lib/data/elections.ts)。`npm run fetch` がここから `data/raw/{回}/` に落とす。
回・執行日・ページ・版は兄弟サイトの目録と同じ（election-sangiin-timeseries の `docs/data-sources.md` §2）。

### 確定と速報

兄弟サイトと同じく、第26回確定結果調（e-Stat）の推移表と突き合わせた第19〜26回を「確定」、確定結果が公表されていない第27回を「速報」とする。
突き合わせた値（`npm run verify`）:

- 「候補者及び競争率」（p.5）の選挙区・比例代表の候補者数
- 「女性候補者数」（p.6）の選挙区・比例代表の女性候補者数
- 「党派別当選人数の推移」の自由民主党の当選人数（比例代表・計）

## 3. 読み方の決まり

表の組み方は回と形式で揺れるので、党の列は党名ではなく小見出し（男・女・計、新・現・元・計）の位置から決め、党名はその上の見出しをつなげて読む（[`src/lib/parse/tables.ts`](../src/lib/parse/tables.ts)）。

- 党名は各回の届出名称のまま。全角英数は半角に寄せ、空白と注記（※1）を除く。2行に折られた党名はつなぐ（第24回「生活の党と」「山本太郎となかまたち」）。兄弟サイトと同じ決まりなので、党名が同じ文字列になる。
- 新前元の「前」（第22回まで）と「現」（第23回から）は同じ区分として読む。画面では「現職」。
- 党派別の表の区分（選挙区・比例代表・合計）は、回によって選挙区と比例代表の順が入れ替わる（第19〜22回は比例代表が先）。区分の名前で決める。名前は縦書きで、PDF では1字ずつ別の行に割れるので、前の区分の計の行から今の区分の計の行までの1列目をつなげて読む。
- 参議院では選挙区と比例代表に重複して立候補できないので、「合計」= 選挙区 + 比例代表。
- 空欄・ダッシュは 0。
- 「4(1)」「(1)」の括弧は、通常選挙と合併して行われた補欠選挙の数（外書）。第26回の神奈川県、第27回の東京都。同じ投票で選ぶので足す（定数も 4(1) → 5）。兄弟サイトの改選数（選挙区 75）と揃う。
- 表の中の「計」（男 + 女、新 + 現 + 元）は読むたびに内訳の和と突き合わせ、合わなければ止める。
- 都道府県別の表の行は選挙区。第24回からの合区は「鳥取県・島根県」「徳島県・高知県」の1行。画面の地図は都道府県のタイルなので、合区の2県を同じ選挙区の値で塗り、全国の人数では1度だけ数える。

### 印字の誤り

- 第19回の当選人数の表（`winPref`）は、最初の組だけ新潟県の定数が 1。同じ表の2つ目の組、候補者数の表、計の行（73）はどれも 2 と合う。`scripts/normalize.ts` の `SEAT_TYPOS` に書き、そのセルだけを読み飛ばす。

### 第20回の PDF

`pdftotext -bbox`（poppler）で語ごとの位置を取り、Excel と同じ行 × 列のセルに組み直してから同じ解析器に通す（[`src/lib/parse/pdf.ts`](../src/lib/parse/pdf.ts)）。

- 列は、小見出しの最も多い行の小見出し1つにつき1列。都道府県別の表の「定数」は縦に2段で組まれ、「数」が小見出しの行にないので、その行より左にある小見出しも列にする。
- 数値は列の右端に揃っているので、数値の右端より左に右端がある最後の小見出しをその列とする。文字は中心が最も近い小見出しの列に置く。

## 4. 突き合わせ（`npm run verify`）

- 党派別: 合計列 = 党の和。合計 = 選挙区 + 比例代表。
- 都道府県別: 計の行 = 選挙区の和。党ごとの計の行 = 党派別の表の選挙区。選挙区の合計 = 党の和。候補者と当選人の表で選挙区と定数が同じ。
- 選挙区: どの都道府県もちょうど1つの選挙区に入る。合区があるのは第24回から。
- 定数: 選挙区の定数の和 = 改選数（選挙区）。選挙区・比例代表の当選人 = 改選数。選挙区の当選人 = その選挙区の定数。
- 確定値: 第19〜26回（§2）。

## 5. 配信データ

`npm run data` が `data/normalized/*.json` と `data/palette.json` だけを入力に、`public/data/` に書き出す。

| ファイル | 次元 | 値 |
| --- | --- | --- |
| `national.json` | 候補者/当選者 × 制度（選挙区・比例代表・全体）× 党 × 回 | 新現元 × 男女の人数 |
| `pref.json` | 回 × 都道府県 | その県が入る選挙区の名前・定数、候補者/当選者 × 党の人数 |
| `palette.json` | 党 | 色相 |

### 党の色

党の色相は兄弟サイト election-sangiin-timeseries の `public/data/palette.json` を `data/palette.json` に写して使う（衆議院のシリーズに出た党は衆議院と同じ色相）。
色相のない党があれば `npm run data` が止まる。兄弟サイトの配色が変わったら写し直す。
