# データソース

「参議院選挙で、得た票はどれだけ議席になったか」のデータソースと、データ層の設計方針。
調査日: 2026-09-26。

## 1. 結論

一次情報源は総務省「参議院議員通常選挙結果調」（兄弟サイトと同じ）。
このサイトは結果調を読み直さない。兄弟サイト2つが結果調から読んで突き合わせた配信データを、党名でつなぐ。

| 値 | 読み元 | 回 |
| --- | --- | --- |
| 得票数・有効投票数（全国、選挙区・比例代表） | [election-sangiin-timeseries](https://github.com/visualizing-jp/election-sangiin-timeseries) の `public/data/era.json` | 第19〜27回 |
| 当選人数（全国、選挙区・比例代表） | [sangiin-candidates](https://github.com/visualizing-jp/sangiin-candidates) の `public/data/national.json`（当選者の新現元 × 男女の和） | 第19〜27回 |
| 党の色相 | election-sangiin-timeseries の `public/data/palette.json` | — |

範囲は兄弟サイトと同じ第19回（2001年）から。衆議院の兄弟サイト（shugiin-seats）にあった手起こしの議席は要らない。

出典表記: 総務省「参議院議員通常選挙結果調」。

### 確定と速報

兄弟サイトと同じく、確定結果が公表されていない第27回を「速報」とする。

## 2. 取得（`npm run fetch`）

兄弟サイトの GitHub リポジトリ（main）から、上の配信データを `data/sibling/{timeseries,candidates}/` に写す。毎回取り直して上書きする。
兄弟サイトのデータや配色が変わったら取り直し、`npm run verify && npm run data` を通す。

## 3. 読み方の決まり

- 党名は兄弟サイトと同じ文字列でつなぐ（各回の届出名称のまま）。別の回の同名・後継の党はつながない。
- 得票率 = 党の得票数 ÷ 有効投票数。議席率 = 党の当選人数 ÷ その回の改選数。差 = 議席率 − 得票率。
- 参議院は3年ごとに半数を改選する。議席はその回の選挙で選んだ議席で、参議院全体の勢力（非改選を含む）ではない。
- 第26回（神奈川県）と第27回（東京都）は、選挙区に補欠選挙1人を合併して行った。同じ投票で選ぶので、得票（兄弟サイトの得票の表）にも議席（兄弟サイトの当選人数、外書きを足したもの）にも含め、改選数は選挙区 75。
- 得票の表に届出のない党は、その回・制度では null（得票も議席も持たない）。届出があって当選のない党の議席は 0。
- 兄弟サイト sangiin-candidates の当選人数の表は、その回に候補のない党も 0 で並べるので、議席 0 で得票がない党は読まない。
- ずれの大きさは Gallagher の最小二乗指数 √(½ Σ(得票率 − 議席率)²)（Gallagher, M. 1991. Proportionality, disproportionality and electoral systems. *Electoral Studies* 10(1), 33–51）。党ごとに数え、諸派・無所属はそれぞれ1つの党とみなす。画面で計算する。

## 4. 突き合わせ（`npm run verify`）

- 議席の党が、どれも同じ回・同じ制度の得票の表にある（党名が同じ文字列でつながる）。
- 制度ごとの議席の和 = 改選数。
- 党の得票の和 ≤ 有効投票数。

## 5. 配信データ

`npm run data` が `data/sibling/` だけを入力に、`public/data/` に書き出す。

| ファイル | 次元 | 値 |
| --- | --- | --- |
| `era.json` | 制度 × 党 × 回 | 得票数・議席数、有効投票数 |
| `palette.json` | 党 | 色相 |
