# コンテンツ運用ガイド

## 名前を決める

トップから選ぶ大分類を「分野」、関連する可視化の入口を「テーマ」、一つの問いをデータで探索する個別ページを「可視化」と呼びます。共通ナビとトップのカードには、同じ分野を同じ名前・順序で表示します。「選挙」などのテーマへの入口は各分野のページに置きます。テーマは複数の可視化をまとめたいときに設けます。

[sites.json](../sites.json) に公開パスとソースの対応を登録します。選挙分野の登録例は次のとおりです。

| 項目 | 参議院の投票率の記入例 |
|---|---|
| 分野 `section` | 政治 |
| テーマ `theme` | 参議院選挙 |
| 短い名前 `shortName` | 参議院選挙の投票率 |
| ページの見出し `title` | 参議院選挙で、どれだけの人が投票したか |
| 公開先 `path` | /politics/elections/sangiin/turnout/ |
| 修正先 `directory` | apps/politics/sangiin-turnout |

一覧カードやパンくずには対象と指標が分かる短い名前を使い、本文の見出しでは読者が探索できる問いを伝えます。統合ビルドでは短い名前をブラウザーや検索向けのページタイトルにも使います。新規追加時は該当分野の一覧からリンクし、台帳と画面の表記を合わせます。既存ページは編集時に順次そろえ、公開済みの URL は維持します。

## 置き場所を決める

- 公式サイトの可視化は `dataofjapan/data-of-japan` の `apps/<分野>/<コンテンツ名>/` に置きます。新しいディレクトリ名は英小文字とハイフンで付けます。
- 一覧には既存の共通生成処理を使います。独自の一覧画面は `portal/` に置きます。
- 可視化専用のデータと加工処理はアプリに同梱し、出典・ライセンス・更新手順をアプリの README に記します。
- 単独で配布・更新するデータセットは GitHub の `dataofjapan` Organization に独立リポジトリを置き、利用する側から参照します。
- 取り込み元は履歴として台帳に残します。管理する旧リポジトリの README には現在の公開先と修正先を案内します。

## 計測を確認する

公式サイトの GA4 プロパティとウェブストリームを共有します。統合ビルドが全ページに共通の `/analytics.js` を一度挿入するため、個別アプリへのタグ追加は不要です。測定 ID は本番環境変数で管理し、本番の公式ドメインで計測します。

初回表示とパス変更は `page_view` 各1回、同じパスでの `view` 切り替えは `view_change` です。通常の絞り込みでは閲覧数を増やしません。分野別は `content_group`（トップは `home`、その他はパスの先頭階層）、可視化別は公開パス、ビュー別は `view_name` で集計します。

追加時はルートで `npm test`、`npm run build`、`npm run check` を実行します。GA4 管理画面の設定と本番での受信確認は [README の Google Analytics 4](../README.md#google-analytics-4) を参照してください。
